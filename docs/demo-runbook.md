# Swaram demo runbook

## Start

Copy `.env.example` to `.env`, set matching random `SUPERVISOR_READ_TOKEN` and `SUPERVISOR_ACTION_TOKEN` values, then run `docker compose up --build`. Open <http://localhost:3000>. The UI and API default to mock mode; the demo never dials phone numbers. Automatic supervisor retries remain disabled unless you explicitly set `SUPERVISOR_AUTO_RETRY=true`.

To prefill a 200-contact campaign for Compose, run `docker compose exec api python -m app.seed_demo`, then refresh the page. For a directly run API, use `uv run --directory apps/api python ../../scripts/seed_demo.py` from the repository root. Alternatively, create a fresh campaign in the UI with the sample CSV.

## Four-minute walkthrough

1. Open **RSVP simulation** and click **Start 3-scenario simulation**. ElevenLabs Agent Testing runs the configured organizer agent against its AI-simulated participant in Yes, No, and Unsure roles.
2. Show the generated conversation transcripts and the outcome captured from the organizer agent's `record_outcome` tool. Confirm the uncertain reply is retained verbatim, then download the results as CSV.
3. Open the Community Design Workshop campaign, showing language, segment, and outcome totals.
4. Expand each script to show English, Hindi, and Malayalam copy. Use a new campaign to show template choice, event details, and CSV import.
5. In the new draft, edit a script and approve all language scripts.
6. Click **Simulate campaign** and watch the outcome cards and masked call list populate; retry non-responders and show the next attempt number.
7. Open **Supervisor** to review campaign analysis and human-review cases. Explain that live ElevenLabs/telephony is a separate phase requiring provider setup and consented test contacts.

The RSVP conversations are generated by ElevenLabs Agent Testing and may consume plan usage. The source Agent ID in `.env` is left unchanged. If it is not already configured for RSVP, the first run creates a dedicated client outcome tool and a separate organizer agent using the source agent's voice and language settings, then caches both resource IDs in the local database. The organizer talks with ElevenLabs' generated AI participant in Yes, No, and Unsure roles; these are natural-language simulation personas, not separately provisioned participant Agent IDs. All tools are mocked during Agent Testing, so no webhook, Exotel/PSTN number, microphone, or phone call is used. The API needs `ELEVENLABS_API_KEY` and the source `ELEVENLABS_AGENT_ID` in `.env`.

The generated organizer prompt asks the RSVP question, permits one clarification, and requires the `record_outcome` tool with a `confirmed | declined | maybe` label and the participant's verbatim answer. Simulation tests use ElevenLabs' current discriminated `type: simulation` schema and mock the attached client tool. If ElevenLabs does not return both the outcome and exact response for each scenario, transcripts are saved for review and the run is reported as failed rather than presenting a guessed RSVP.

## Reset local demo data

Remove the `swaram-data` and `supervisor-data` volumes with `docker compose down -v` only when you want to erase all local campaigns, supervisor review records, and generated encryption keys. Recreate the seeded example by running the seed command again.
